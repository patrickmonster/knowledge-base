# 작업 프롬프트

소유자·관리자가 자주 시키는 작업의 지시를 미리 저장해 두면, 참여자가 AI에게 이름이나 호출 문구로 "~해줘"라고 요청할 때 AI가 그 지시를 가져와 그대로 진행한다. 웹 **작업 프롬프트** 메뉴(사이드바의 현재 프로젝트 기준)와 MCP 도구로 다룬다.

예: 이름 `deploy-check`, 호출 문구 `배포 점검`, 본문 "`{{env}}` 서버의 `get_server_version`을 확인하고 …" → 사용자가 "운영 배포 점검해줘"라고 하면 AI가 `get_task_prompt(request: "운영 배포 점검해줘")`로 본문을 받아 진행한다.

## 저장 항목
| 항목 | 제한 |
| --- | --- |
| 이름(`name`) | 프로젝트 안에서 고유, 영문 소문자·숫자·하이픈 1–63자 |
| 제목(`title`) | 1–200자 |
| 설명(`description`) | 선택, 1000자 이하 |
| 호출 문구(`triggers`) | 최대 10개, 각 1–100자. 대소문자·공백·문장부호를 무시하고 비교하며, 같은 문구는 하나로 합친다 |
| 본문(`body`) | 1–20000자. AI가 따를 지시 |
| 인자(`arguments`) | 최대 10개. `name`(영문 소문자·숫자·밑줄, 문자로 시작), `description`(200자 이하), `required`. 본문의 `{{name}}` 자리에 채운다. 선언하지 않은 `{{…}}`를 본문에 쓰면 저장을 거부한다 |

- 프로젝트당 100개. 수정은 `prompt_id`와 `expected_revision`이 필요하고, 다른 사람이 먼저 바꿨거나 다른 프롬프트와 이름이 겹치면 `CONFLICT`.
- 사용/미사용 스위치로 지우지 않고 끌 수 있다. 미사용 프롬프트는 실행(`get_task_prompt`)·호출 문구 비교·작업 맥락에서 빠진다.
- 감사 로그에는 프롬프트 ID만 남고 이름·본문·인자 값은 복사하지 않는다.

## 권한
본문은 검색 결과와 달리 AI가 따르는 **지시**이므로 소유자 규칙과 같은 수준으로 관리한다.

- 추가·수정·삭제·사용 전환: 소유자·관리자, **웹 화면 전용**(MCP 키는 `FORBIDDEN`). 쓰기 키를 가진 AI가 모든 참여자에게 적용될 지시를 바꾸지 못하게 한다.
- 조회·실행: 참여자 전원(조회자 포함, 읽기 전용 키 가능).
- `list_task_prompts`의 `can_manage`는 이번 호출로 바꿀 수 있는지를 뜻한다(소유자·관리자의 웹 세션만 `true`).

## AI 사용
1. `resolve_project`(일치할 때)와 `start_task`/`get_task_context`의 `task_prompts`에 사용 중인 프롬프트 목록(이름·제목·설명·호출 문구·인자, 본문 제외, 최대 50개)이 담긴다. 없으면 생략한다.
2. 사용자의 요청이 프롬프트 이름이나 호출 문구를 담고 있으면 `get_task_prompt`를 부른다.
   - `name` 또는 `prompt_id`: 그 프롬프트를 가져온다(미사용·없음은 `NOT_FOUND`).
   - `request`: 사용자의 말을 그대로 넘긴다. 이름이나 호출 문구가 요청에 들어 있는 프롬프트가 **정확히 하나**면 `matched: true`, 여럿이면 `candidates`(사용자에게 고르게 한다), 없으면 `matched: false`(평소처럼 처리).
   - `arguments`: 인자 값(각 4000자 이하). 필수 인자가 비면 본문의 그 자리를 남기고 `missing_arguments`로 알려 주므로, AI는 사용자에게 값을 묻고 다시 부른다. 선택 인자가 비면 빈 문자열로 채운다. 선언되지 않은 인자 이름은 `INVALID_INPUT`.
3. 응답의 `instructions`(인자를 채운 본문)를 사용자의 요청으로 보고 진행한다. 프로젝트 규칙은 그대로 적용되며 충돌하면 규칙이 우선한다. 변경 작업이면 평소처럼 `start_task`·`finish_task`를 쓴다.
4. 사용자가 요청하지 않은 프롬프트는 실행하지 않는다. MCP 서버 instructions에도 같은 안내가 있다.

MCP 표준 prompts 기능(`prompts/list`)은 쓰지 않았다. 하나의 연결이 여러 프로젝트를 다루고 프로젝트마다 목록이 달라서, 프로젝트를 고른 뒤 도구로 가져오는 방식이 맞다.
