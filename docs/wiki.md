# 프로젝트 위키

프로젝트의 위키는 기획서와 산출물에서 확인한 내용을 주제별 Markdown 글로 정리하는 공간이다. 원본 파일은 첨부 저장소에, 원본 텍스트와 추출 본문은 지식 문서에, 정리한 글은 `wiki` 문서에 저장한다.

## 웹에서 사용하기

1. **위키 → 원본 문서 등록**에서 기획 원문 또는 파일 설명을 저장한다. 파일이 있으면 원본 문서에서 **이 문서에 원본 파일 올리기**를 선택한 후 첨부 화면에서 업로드한다. 파일만 있는 경우 **원본 파일 올리기**로 바로 저장할 수 있다. 본문을 추출할 수 있는 PDF·Word·Excel 파일은 별도의 본문 문서가 생긴다.
2. **위키 글 쓰기**에서 제목, **작업 영역**, Markdown 본문을 작성한다. 본문에 제목을 두 개 이상 사용하면 목차가 표시된다. 목록의 영역 묶음에서 **이 영역에 글 쓰기**를 누르면 그 영역이 미리 선택된다.
3. 저장한 글의 **문서 관계 → 원본 자료**에서 원본 문서나 첨부 본문 문서를 연결한다. 원본 파일은 연결한 문서를 열어 다운로드할 수 있다. 다른 위키 글은 **관련 문서**로 연결한다.
4. 작성한 글은 검토 대기로 저장할 수 있다. 확정된 글은 위키 검색의 기본 대상이다. 상태 선택에서 검토 대기와 보관 글을 따로 찾을 수 있다. 검색은 프로젝트의 기존 키워드·의미 검색 설정을 따른다.

## 목록과 섹션 편집

- 검색어 없이 위키를 열면 글이 **작업 영역별**로 묶여 보인다(이슈 · 질의의 공통 작업 영역과 같은 목록). 영역 이름 옆에 담당자가 표시되고, 영역이 없는 글은 **영역 없음**에 모인다. 위쪽 영역 버튼으로 해당 묶음으로 이동한다. 검색어를 넣으면 기존처럼 관련도 순 목록이 나온다. 한 번에 최대 1000개 글을 묶어 보여 준다.
- 글 보기에서 섹션 제목에 마우스를 올리면 **편집** 버튼이 나타난다(터치 화면은 항상 표시). 누르면 그 섹션(하위 제목 포함)만 그 자리에서 Markdown 편집창으로 바뀐다. 제목 앞 도입부도 같은 방식으로 고친다.
- 섹션 저장은 수정 이유를 비워 두면 `섹션 '<제목>' 수정`으로 기록된다. 바뀐 섹션만 `update_document`의 `edits`로 보내고, 같은 텍스트가 본문에 두 번 이상 있거나 20000자를 넘으면 본문 전체를 보낸다. 다른 사람이 먼저 고쳤으면(버전 충돌) 저장하지 않고 **최신 버전 불러오기**를 안내한다.
- 글 전체를 고치거나 제목·상태·작업 영역을 바꿀 때는 **최신 버전 수정**을 쓴다. 이전 버전을 고른 상태에서는 섹션 편집이 보이지 않는다.
- 작업 영역을 지우면 그 영역의 글은 삭제되지 않고 **영역 없음**으로 옮겨진다.

프로젝트 편집자 이상이 글을 작성·수정할 수 있다. 수정에는 변경 이유가 필요하며 글에서 이전 버전을 열어볼 수 있다. 원본 링크는 글의 현재 관계로 관리한다. 특정 원본 버전을 근거로 삼을 때는 링크 메모나 본문에 버전 번호를 남긴다.

## LLM으로 정리하기

1. 첨부 파일을 `list_attachments`로 찾는다. 추출된 파일은 `text_document_id`가 있는 문서를 `get_document`로 읽는다. 원본이 별도 기획 문서에 있으면 그 문서를 읽는다. 자료를 가져오는 도구가 없는 형식이나 추출이 비어 있는 스캔본은 원문 확인이 필요하다.
2. `search_knowledge`에 `kind: "wiki"`를 넣어 기존 글을 찾는다. 내용이 같은 글이 있으면 최신 버전을 읽고 `update_document`에 `expected_revision`과 `reason`을 넣어 수정한다. 새 주제는 `create_document`에 `kind: "wiki"`와 `status: "draft"`를 넣어 작성한다. 주제에 맞는 공통 작업 영역이 있으면 `list_work_areas`로 찾아 `area_id`를 함께 넣는다.
3. `link_documents`에 `relation: "cites"`, `source_id`에 위키 글 ID, `target_id`에 원본 문서 또는 추출 본문 ID를 넣는다. 원본 버전과 파일의 쪽·시트 등 확인 위치를 메모하거나 본문에 남긴다. 자료가 서로 충돌하면 근거와 미확정 사항을 글에 적는다.
4. 검토 후 확정된 글을 찾으려면 `search_knowledge`에 `project_id`, `kind: "wiki"`, `query`를 보낸다. 업로드와 요약 실행은 별도 단계이며, 연결된 LLM 클라이언트에 정리를 요청하면 위 절차로 작성한다.
