# 할 일 보드

프로젝트의 가벼운 할 일을 칸반 보드로 관리한다. 웹 콘솔 **할 일 보드** 화면과 MCP 도구가 같은 데이터(`todos` 테이블, `migrations/025_todos.sql`)를 쓴다.

## 화면

- 열: 상태 — 시작 전(`not_started`), 진행 중(`in_progress`), 검토대기(`in_review`), 완료(`completed`), 아이디어(`idea`). 머리에 건수 표시.
- 행: 우선순위 — 높음(`high`), 보통(`medium`), 낮음(`low`). 행 머리를 눌러 접고 펼친다(브라우저에 기억).
- 숨기기: 필터 줄의 “숨기기”(숨긴 항목이 있으면 “숨김 N”) 버튼으로 상태 열이나 우선순위 행을 체크 해제해 숨기고, 다시 체크하거나 “모두 보이기”로 되돌린다. 행 접기와 달리 행 머리째 사라지며, 열·행마다 하나는 항상 남는다. 설정은 브라우저(localStorage)에만 저장되어 서버·다른 기기에는 영향이 없다. 숨긴 칸의 카드도 데이터는 그대로이고 건수 옆에 “숨김 n건”으로 표시된다(완료 체크로 숨긴 열로 보내면 안내 메시지가 나온다).
- 카드: 제목, 상태, 분류, 완료 체크, 진행률 막대(설정한 경우), 담당자·마감일(지난 마감은 빨간색).
- 카드를 끌어 다른 칸이나 다른 카드 앞에 놓으면 `move_todo`로 저장된다. 휴대폰·태블릿에서는 카드를 길게 눌러(약 0.35초) 집은 뒤 끌어 놓는다. 짧게 미는 동작은 평소처럼 보드를 스크롤하고, 집은 채 화면 가장자리에 대면 보드가 옆·위아래로 따라 움직인다. 키보드 사용자는 카드에서 Enter로 수정 창을 열어 상태·우선순위를 바꾼다.
- 완료 체크는 완료 열로, 해제는 진행 중 열로 옮긴다. 진행률이 있는 카드를 완료로 옮기면 100%가 된다.
- 검토대기는 만들기·검토 요청이 끝나 리뷰·확인을 기다리는 카드다. 자동으로 옮겨지지 않으며(진행 중·완료 자동 이동은 그대로), 끌어 놓기·수정 창·`move_todo`/`save_todo`로 직접 지정한다(`migrations/036_todo_in_review.sql`).
- 보드 아래 “열린 이슈 · 질의” 목록에 답변 대기·답변됨 질의·이슈(최대 30건)와 연결된 할 일, 작업 보류 표시를 보여 준다. 자세한 처리는 이슈 · 질의 화면에서 한다.
- 칸의 “새로 만들기”는 그 칸의 상태·우선순위로 새 할 일 창을 연다.
- 필터: 분류, 내게 배정된 것만. 한 번에 최대 500건 표시.

## 권한

- 조회: 프로젝트 참여자 모두(조회자 포함, 수정 창은 읽기 전용).
- 추가·수정·이동·삭제: 편집자·관리자·소유자. 읽기 전용 MCP 키는 거부된다.
- 담당자는 활성 상태의 프로젝트 참여자만 지정할 수 있다.
- 프로젝트당 최대 5000건.

## MCP 도구

| 도구 | 설명 |
| --- | --- |
| `list_todos` | 보드 순서(우선순위 → 상태 → 위치)로 목록. `status`, `priority`, `category`, `assignee_id`, `mine`, `limit`(최대 500) |
| `save_todo` | `todo_id` 없이 추가(칸 맨 끝). 수정은 `todo_id`와 `expected_revision`, 모든 필드를 바꾸므로 유지할 값도 보낸다(생략한 `progress`·`assignee_id`·`due_date`는 지워짐). 상태·우선순위가 바뀌면 새 칸 맨 끝으로 간다 |
| `move_todo` | `status`·`priority` 칸으로 옮기고 `before_id` 앞(생략 시 맨 끝)에 놓는다 |
| `delete_todo` | 영구 삭제 |

## 진행 중 작업과 연결

할 일 하나에 AI 작업(`start_task` 실행) 여러 개가 붙을 수 있다(`task_runs.todo_id`, `migrations/026_todo_task_link.sql`).

- 연결: `start_task`의 `todo_id`, 또는 이미 시작한 열린 작업에 `link_task_todo`(작업을 시작한 사람·소유자·관리자). 웹에서는 **진행 중 작업** 카드의 “할 일 연결”.
- 시작: 연결하면 시작 전·아이디어 할 일이 진행 중 열 맨 끝으로 옮겨진다. 이미 진행 중·완료면 그대로 둔다.
- 후보: `start_task`·`get_task_context`의 `context.todos.candidates`에 작업 설명과 단어가 겹치는 미완료 할 일(최대 5건)을, `context.todos.linked`에 연결된 할 일을 준다.
- 완료: `finish_task`가 `completed`면 할 일을 완료로 옮기고 진행률이 있으면 100%로 채운다. `partial`·`blocked`·`cancelled`는 그대로 둔다.
- PR 병합: 연결 작업의 추적 PR이 모두 끝났고(병합·배포·닫힘, 이 서버 저장소는 배포까지) 하나 이상 병합되면, PR 상태를 history에 기록하는 시점에 할 일도 완료로 옮긴다. 부분 완료로 PR만 올린 작업도 변경이 반영되면 할 일이 끝난다.
- 표시: 보드 카드에 “작업 N · 진행 중 n”과 최근 PR 상태, 수정 창에 연결된 작업 목록(`list_task_runs`의 `todo_id` 필터). 진행 중 작업 카드에 연결된 할 일 제목.
- 할 일을 삭제해도 작업 기록은 남고 연결만 풀린다. 자동 이동은 작업을 끝낸 사람 이름으로 기록된다.

## 이슈·질의와 연결

질의·이슈 하나는 할 일 하나에 속할 수 있고, 할 일 하나에 여러 질의가 모인다(`issues.todo_id`, `migrations/027_issue_todo_link.sql`).

- 연결: `create_issue`의 `todo_id`, 또는 `link_issue_todo`(편집자 이상, 빈 `todo_id`는 해제). 웹에서는 새 질의 양식의 “할 일”, 질의 카드의 “할 일 연결”.
- 자동 연결: `create_issue`에 `task_id`만 넘기면 그 작업에 연결된 할 일로 들어간다. 할 일을 수행하던 AI가 남긴 질의가 그 할 일에 모인다.
- 표시: 보드 카드에 “질의 n”(답변 대기·답변됨)과 “보류 n”(답변 대기 중인 작업 보류 질의), 할 일 수정 창에 연결된 질의·이슈 목록(`list_issues`의 `todo_id` 필터), 질의 카드에 할 일 제목.
- AI 안내: `context.todos.linked`·`candidates`에 `open_issues`, `blocking_issues`가 붙는다. 보류 질의가 남아 있으면 AI는 `list_issues(todo_id)`로 읽고 진행 전에 사용자에게 확인한다.
- 질의 상태는 할 일을 옮기지 않는다. 보류 질의가 열려 있어도 작업 완료·PR 반영에 따른 자동 완료는 그대로 일어난다.
- 할 일을 삭제해도 질의·이슈는 남고 연결만 풀린다.

## 내보내기·가져오기

프로젝트 내보내기(JSON·Markdown zip)에 할 일이 들어가고, 가져오기는 할 일을 새로 만든다. 보드 위치·분류·진행률·마감일은 유지하고 담당자와 작업·PR·질의 연결은 가져오지 않는다. 자세한 규칙은 [team-rollout.md](team-rollout.md)의 “프로젝트 내보내기·가져오기”를 참고한다.

## 정렬 위치

칸 안 순서는 `position`(오름차순)이다. 새 카드는 칸의 최댓값 + 1024, 카드 사이에 놓으면 앞뒤의 중간값을 쓴다. 간격이 1e-6 이하로 줄면 그 칸을 1024 간격으로 다시 매긴다. 동시에 같은 칸에 놓는 요청이 같은 간격을 고르지 않도록 이동은 프로젝트 단위 advisory lock 안에서 처리한다.

## 감사 기록

`todo_id`, `status`, `priority`, `category`, `before_id`만 감사 입력으로 남기고 제목·내용은 복사하지 않는다.
