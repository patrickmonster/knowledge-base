# 할 일 보드

프로젝트의 가벼운 할 일을 칸반 보드로 관리한다. 웹 콘솔 **할 일 보드** 화면과 MCP 도구가 같은 데이터(`todos` 테이블, `migrations/025_todos.sql`)를 쓴다.

## 화면

- 열: 상태 — 시작 전(`not_started`), 진행 중(`in_progress`), 검토대기(`in_review`), 반영 대기(`pending_release`), 아이디어(`idea`). 머리에 건수 표시. 완료(`completed`)는 보드에 열로 두지 않고 **완료된 할 일** 화면에서 따로 본다.
- 행: 우선순위 — 높음(`high`), 보통(`medium`), 낮음(`low`). 행 머리를 눌러 접고 펼친다(브라우저에 기억).
- 검색: 필터 줄의 검색 칸에 낱말을 넣으면 제목·본문·분류에 그 낱말이 모두 들어 있는 카드만 남는다(대소문자 구분 없음, 이미 불러온 카드를 거르므로 서버를 다시 부르지 않는다). 완료된 할 일 화면에도 같은 칸이 있다.
- 숨기기: 필터 줄의 “숨기기”(숨긴 항목이 있으면 “숨김 N”) 버튼으로 상태 열이나 우선순위 행을 체크 해제해 숨기고, 다시 체크하거나 “모두 보이기”로 되돌린다. 행 접기와 달리 행 머리째 사라지며, 열·행마다 하나는 항상 남는다. 설정은 브라우저(localStorage)에만 저장되어 서버·다른 기기에는 영향이 없다. 숨긴 칸의 카드도 데이터는 그대로이고 건수 옆에 “숨김 n건”으로 표시된다.
- 카드: 제목, 상태, 분류, 완료 체크(진행 중·검토대기·반영 대기 카드만), 작업 브랜치(입력한 경우, 반영 대기인데 비어 있으면 “브랜치 미입력”), 진행률 막대(설정한 경우), 담당자·마감일(지난 마감은 빨간색). 하위 항목이면 제목 위에 “↳ 상위 제목”, 하위 항목이 있으면 “하위 완료/전체”, 선행 할 일이 남아 있으면 “선행 대기 n”(모두 끝나면 “선행 완료”)이 붙는다.
- 카드를 끌어 다른 칸이나 다른 카드 앞에 놓으면 `move_todo`로 저장된다. 휴대폰·태블릿에서는 카드를 길게 눌러(약 0.35초) 집은 뒤 끌어 놓는다. 짧게 미는 동작은 평소처럼 보드를 스크롤하고, 집은 채 화면 가장자리에 대면 보드가 옆·위아래로 따라 움직인다. 키보드 사용자는 카드에서 Enter로 수정 창을 열어 상태·우선순위를 바꾼다.
- 진행 중·검토대기·반영 대기 카드의 완료 체크는 할 일을 완료로 옮기고 보드에서 뺀다(시작 전·아이디어 카드에는 체크가 없다). 진행률이 있는 카드를 완료로 옮기면 100%가 된다.
- 완료된 할 일: 사이드바 또는 보드 필터 줄의 “완료된 할 일 N건” 버튼으로 연다. 완료일 최신순 표(완료일·제목·우선순위·분류·담당자·연결된 작업/PR/질의)이며 분류·내 담당 필터가 있다. 제목을 누르면 수정 창이 열리고, 편집 권한이 있으면 “진행 중으로 되돌리기”로 보드에 다시 올린다. `list_todos(status: completed)`로 최대 500건 표시.
- 검토대기는 만들기·검토 요청이 끝나 리뷰·확인을 기다리는 카드다. 자동으로 옮겨지지 않으며(진행 중·완료 자동 이동은 그대로), 끌어 놓기·수정 창·`move_todo`/`save_todo`로 직접 지정한다(`migrations/036_todo_in_review.sql`).
- 반영 대기는 리뷰가 끝나 작업 브랜치의 병합·배포를 기다리는 카드다(검토대기 다음, 완료 앞). 카드를 이 열로 끌어 놓으면 작업 브랜치를 묻는다(취소하면 옮기지 않는다). 수정 창의 “작업 브랜치” 칸에서도 바꿀 수 있다. 브랜치를 비워 두고 반영 대기로 옮기면 서버가 연결된 AI 작업(`start_task`의 `branch`) 중 가장 최근 것의 브랜치로 채운다. 반영 대기 카드는 자동으로 완료되지 않는다. 연결 작업을 `finish_task` completed로 닫거나 연결 작업의 PR이 병합돼도(예: dev 머지) 반영 대기에 남고, 반영을 확인한 사람이 완료로 옮긴다. 예외로 이 서버 저장소의 PR이 실행 중인 서버에 배포된 것(`deployed`)까지 확인되면 완료로 옮긴다(`migrations/046_todo_pending_release.sql`).
- MCP: `save_todo`·`move_todo`의 `branch`(200자 이하, 공백·제어 문자 불가, 빈 문자열은 지움, 생략하면 유지). `list_todos` 결과에 `branch`가 있다.
- 보드 아래 “열린 이슈 · 질의” 목록에 답변 대기·답변됨 질의·이슈(최대 30건)와 연결된 할 일, 작업 보류 표시를 보여 준다. 자세한 처리는 이슈 · 질의 화면에서 한다.
- 칸의 “새로 만들기”는 그 칸의 상태·우선순위로 새 할 일 창을 연다.
- 필터: 분류, 내게 배정된 것만, 오래 묵은 것만(해당 카드가 있을 때만 보임). 한 번에 최대 500건 표시.
- 오래 묵은 할 일: 아래 [오래 묵은 할 일 정리 안내](#오래-묵은-할-일-정리-안내) 기준에 걸린 카드에 “N일 정체” 표시와 왼쪽 강조선이 붙는다.

## 권한

- 조회: 프로젝트 참여자 모두(조회자 포함, 수정 창은 읽기 전용).
- 추가·수정·이동·삭제: 편집자·관리자·소유자. 읽기 전용 MCP 키는 거부된다.
- 담당자는 활성 상태의 프로젝트 참여자만 지정할 수 있다.
- 프로젝트당 최대 5000건.

## MCP 도구

| 도구 | 설명 |
| --- | --- |
| `list_todos` | 보드 순서(우선순위 → 상태 → 위치)로 목록. `status`, `priority`, `category`, `assignee_id`, `mine`, `query`, `limit`(최대 500) |
| `save_todo` | `todo_id` 없이 추가(칸 맨 끝). 수정은 `todo_id`와 `expected_revision`, 모든 필드를 바꾸므로 유지할 값도 보낸다(생략한 `progress`·`assignee_id`·`due_date`는 지워짐). 상태·우선순위가 바뀌면 새 칸 맨 끝으로 간다. 관계 필드 `parent_id`·`blocked_by`는 생략하면 그대로 둔다(아래 “선후 관계와 하위 항목”) |
| `move_todo` | `status`·`priority` 칸으로 옮기고 `before_id` 앞(생략 시 맨 끝)에 놓는다 |
| `delete_todo` | 영구 삭제 |
| `list_stale_todos` | 오래 움직이지 않은 대기 할 일을 오래된 순으로. `older_than_days`(1–365, 기본 14), `limit`(최대 200). 읽기 전용, 참여자 모두 |

## 선후 관계와 하위 항목

“ClamAV 결정 → EICAR 시험”처럼 순서가 있는 묶음을 표현한다(`migrations/043_todo_relations.sql`).

- 하위 항목(`parent_id`): 할 일을 다른 할 일 아래에 둔다. 한 단계만 허용한다 — 상위 할 일은 다른 할 일의 하위가 될 수 없고, 하위 항목이 있는 할 일은 하위가 될 수 없다. 상위 할 일을 지우면 하위 항목은 남고 최상위로 올라온다.
- 선행 할 일(`blocked_by`): 이 할 일보다 먼저 끝나야 하는 할 일 목록(최대 20개). 순환(A가 B를, B가 A를 기다림 — 간접 포함)은 저장할 때 거부한다. 어느 쪽이든 지우면 관계도 지워진다.
- 두 관계 모두 같은 프로젝트의 할 일끼리만 맺는다.
- 표시 전용이다: 선행 할 일이 남아 있어도 이동·완료를 막지 않고, 하위 항목을 모두 끝내도 상위 할 일은 자동으로 완료되지 않는다. 보드 칸 배치(상태 × 우선순위)도 그대로다.
- `save_todo`: `parent_id`에 상위 ID(빈 문자열은 해제), `blocked_by`에 ID 목록(`[]`은 해제, 목록 전체를 바꿈)을 보낸다. 생략하면 기존 관계를 유지한다 — 다른 필드와 달리 생략이 지우기가 아니어서, 관계를 모르는 클라이언트가 수정해도 관계가 사라지지 않는다.
- `list_todos` 응답: `parent_id`, `parent_title`, `blocked_by`(각 `id`·`title`·`status`), `open_blocker_count`(아직 완료되지 않은 선행 수), `subtask_count`, `subtasks_completed`.
- 웹: 할 일 보드의 수정 창에서 “상위 할 일”을 고르고, “먼저 끝나야 하는 할 일” 목록(검색 가능)에서 체크한다. 하위 항목과 이 할 일을 기다리는 할 일도 함께 보여 준다. 웹은 바뀐 관계만 보낸다. 완료된 할 일 화면의 수정 창에서는 관계를 읽기만 한다(그 화면은 완료된 할 일만 불러와 고를 대상이 모자라기 때문).
- 바꾸는 동안 프로젝트 단위 advisory lock으로 직렬화해 동시 저장이 함께 순환이나 두 번째 단계를 만들지 못하게 한다.

## 진행 중 작업과 연결

할 일 하나에 AI 작업(`start_task` 실행) 여러 개가 붙을 수 있다(`task_runs.todo_id`, `migrations/026_todo_task_link.sql`).

- 연결: `start_task`의 `todo_id`, 또는 이미 시작한 열린 작업에 `link_task_todo`(작업을 시작한 사람·소유자·관리자). 웹에서는 **진행 중 작업** 카드의 “할 일 연결”.
- 해제: `link_task_todo`에 빈 `todo_id`. 열린 작업뿐 아니라 완료·중단된 작업도 해제할 수 있다(잘못 붙인 연결 정리용, 같은 권한). 해제해도 할 일의 상태는 바뀌지 않고, 할 일의 작업 수·PR 목록에서 그 작업이 빠진다. 닫힌 작업은 다시 연결할 수 없다. 웹에서는 진행 중 작업 화면의 닫힌 작업 카드 “할 일 연결 해제”, 할 일 수정 창 “연결된 AI 작업”의 “연결 해제”.
- 시작: 연결하면 시작 전·아이디어 할 일이 진행 중 열 맨 끝으로 옮겨진다. 이미 진행 중·완료면 그대로 둔다.
- 후보: `start_task`·`get_task_context`의 `context.todos.candidates`에 작업 설명과 단어가 겹치는 미완료 할 일(최대 5건)을, `context.todos.linked`에 연결된 할 일을 준다.
- 완료: `finish_task`가 `completed`면 할 일을 완료로 옮기고 진행률이 있으면 100%로 채운다. `partial`·`blocked`·`cancelled`는 그대로 둔다.
- PR 병합: 연결 작업의 추적 PR이 모두 끝났고(병합·배포·닫힘, 이 서버 저장소는 배포까지) 하나 이상 병합되면, PR 상태를 history에 기록하는 시점에 할 일도 완료로 옮긴다. 부분 완료로 PR만 올린 작업도 변경이 반영되면 할 일이 끝난다.
- 표시: 보드 카드에 “작업 N · 진행 중 n”과 최근 PR 상태, 수정 창에 연결된 작업 목록(`list_task_runs`의 `todo_id` 필터). 진행 중 작업 카드에 연결된 할 일 제목.
- 할 일을 삭제해도 작업 기록은 남고 연결만 풀린다. 자동 이동은 작업을 끝낸 사람 이름으로 기록된다.

## 이슈·질의와 연결

질의·이슈 하나는 할 일 하나에 속할 수 있고, 할 일 하나에 여러 질의가 모인다(`issues.todo_id`, `migrations/027_issue_todo_link.sql`).

- 연결: `create_issue`의 `todo_id`, 또는 `link_issue_todo`(편집자 이상, 빈 `todo_id`는 해제). 웹에서는 새 질의 양식의 “할 일”, 질의 카드의 “할 일 연결”.
- 자동 연결: `create_issue`에 `task_id`만 넘기면 그 작업에 연결된 할 일로 들어간다. 할 일을 수행하던 AI가 남긴 질의가 그 할 일에 모인다.
- 표시: 보드 카드에 “질의 n”(답변 대기·답변됨)과 “보류 n”(답변 대기 중인 작업 보류 질의), 할 일 수정 창에 연결된 질의·이슈 목록(`list_issues`의 `todo_id` 필터), 질의 카드에 할 일 제목.
- AI 안내: `context.todos.linked`·`candidates`에 `open_issues`, `blocking_issues`가 붙는다. 보류 질의가 남아 있으면 AI는 `list_issues(todo_id)`로 읽고 진행 전에 사용자에게 확인한다.
- 질의 상태는 할 일을 옮기지 않는다. 보류 질의가 열려 있어도 작업 완료·PR 반영에 따른 자동 완료는 그대로 일어난다.
- 할 일을 삭제해도 질의·이슈는 남고 연결만 풀린다.

## 오래 묵은 할 일 정리 안내

진행 중 작업에 `cleanup_stale_task_runs`가 있듯, 할 일 보드에도 오래 멈춘 카드를 드러내 정리를 돕는다(`internal/kb/todo_stale.go`). 자동으로 옮기거나 지우지 않는다.

- 대상: 시작 전·진행 중·검토대기 할 일. 아이디어는 보관용이고 완료는 끝났으므로 제외한다.
- 마지막 활동: 할 일 자체의 수정·이동(`updated_at`), 연결된 작업의 시작·완료·중단, 연결된 질의·이슈의 변경 중 가장 최근 시각. 이 시각이 기준일(기본 14일)보다 오래되면 오래 묵은 할 일이다.
- `list_stale_todos`: 오래된 순으로 `idle_days`(멈춘 날수), `last_activity_at`, 담당자, 열린 연결 작업 수와 전체 건수(`total`)를 준다. 기준일은 호출마다 `older_than_days`로 바꿀 수 있다.
- 작업 시작 맥락: `start_task`·`get_task_context`의 `context.todos.stale`에 14일 넘게 멈춘 할 일을 오래된 순으로 최대 5건과 전체 건수를 준다. 없으면 필드가 빠진다. AI는 이를 사용자에게 보드 정리 제안으로 알리고, 요청 없이 옮기거나 지우지 않는다.
- 보드: 카드에 “N일 정체”, 필터 줄에 “14일 넘게 멈춘 것만 (N)” 체크.
- 기준일 14일은 서버 상수(`defaultStaleTodoDays`)다. 운영 설정 화면으로 바꾸게 하려면 별도 저장 위치가 필요하다(후속).

## 내보내기·가져오기

프로젝트 내보내기(JSON·Markdown zip)에 할 일이 들어가고, 가져오기는 할 일을 새로 만든다. 보드 위치·분류·진행률·마감일과, 함께 새로 만든 할 일 사이의 상위·선행 관계는 유지하고 담당자와 작업·PR·질의 연결은 가져오지 않는다. 상대 할 일이 이미 있어 건너뛰었거나 규칙에 맞지 않는 관계는 빼고 경고로 알린다. 자세한 규칙은 [team-rollout.md](team-rollout.md)의 “프로젝트 내보내기·가져오기”를 참고한다.

## 정렬 위치

칸 안 순서는 `position`(오름차순)이다. 새 카드는 칸의 최댓값 + 1024, 카드 사이에 놓으면 앞뒤의 중간값을 쓴다. 간격이 1e-6 이하로 줄면 그 칸을 1024 간격으로 다시 매긴다. 동시에 같은 칸에 놓는 요청이 같은 간격을 고르지 않도록 이동은 프로젝트 단위 advisory lock 안에서 처리한다.

## 감사 기록

`todo_id`, `status`, `priority`, `category`, `before_id`만 감사 입력으로 남기고 제목·내용은 복사하지 않는다.
